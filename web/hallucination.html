Project 03

LLM Hallucination Tester

Generates factual questions, answers them, then grades each answer against a retrieved source — and shows you the passage the verdict rested on.

StackFastAPI · LangChain · async
Pipeline3 stages · 2N+1 calls
GradingRetrieved passages
The problem

I built this because I was tired of models stating nonsense with total confidence. If you're shipping a RAG pipeline you want a number — how often does this model just make things up? — and you want it before it reaches users, not after.

The first version had a flaw I'd have been asked about in any interview: it graded one model's answers using another model's memory. That's not measurement, it's two guesses stacked. So stage three now checks each answer against retrieved reference passages, and returns the passage alongside the verdict. The grader can be audited.

How it works
01

Generate

One call produces N factual, verifiable questions about the chosen topic.

02

Answer

The model answers each question. Concurrency is capped at two so the rate limit holds.

03

Grade

Each answer is checked against passages retrieved from the reference corpus — not model memory.

04

Report

A hallucination rate, plus per-question verdict, reasoning, and the supporting passage.

Topics are limited to the indexed corpus by design. A free-text box would silently fall back to ungrounded judgement, which is exactly the failure this tool exists to catch.

Cost is 2N+1 model calls — one to generate, N to answer, N to grade. At three questions that's seven, which is why num_questions is clamped server-side regardless of what the client sends.

How these demos handle your data
What is sent
Only the text you type into a demo box, capped at 2,000 characters. Nothing else about you or your browser.
Where it goes
A container on Google Cloud Run that wakes on request and sleeps after, which calls the Google Gemini API. Free-tier prompts may be used by Google to improve their models.
What is retained
Nothing. Request bodies are never logged — only timestamp, path and status code.
Limits
Five runs per hour per visitor, and outbound model calls are capped at two concurrently. When a limit is reached you'll see a cached sample result rather than an error.
Uploads
Not accepted. File parsing exists in the repositories but is deliberately left out of the public demos.
